# Build from a Paper link

An explicit request to build a Paper page authorizes the approved designs on
that page. Use its Ready for build card to find exact artboard names, visual
criteria, routes, verification setup, and runtime behavior. For a requested
multi-page handoff, include the other approved pages in that scope. Treat other
links as references and filter the card's inventory to the requested pages.
If the card is absent, look for an equivalent approved inventory and criteria in
the request or repository. Ask about scope or behavior that remains unclear.

With Paper MCP, load the Paper guide and resolve the exact boards on the linked
pages. Use JSX, computed styles, and assets for exact design values. Use
screenshots for the visual comparison. If Paper access is unavailable, use
the approved handoff and saved design exports when they supply the same
details, and report any missing references. Reuse the host project's components
and tokens and apply its existing decisions and journey rules.

Resolve the required devices from the user or host project, then freeze the
approved artboard list and run the inventory check before editing using the
[Paper coverage format](../../verify/references/paper-coverage.md).
Report any required device or screen missing from the design as an incomplete
handoff. A separately authorized subset can proceed on its own.
For presentation changes, implement the visual criteria and run the project's
focused checks. For behavior changes, use the approved journeys and the build
steps for their tasks. Group related work internally and continue through the
full authorized handoff. Record blocked states and continue independent work.

Run the verify skill once across the handoff's approved states and relevant
journey criteria. Return one coverage report with the browser evidence and
any unresolved results. The Paper checker must pass before claiming the whole
handoff is complete. Follow the host project's Git and delivery rules.
